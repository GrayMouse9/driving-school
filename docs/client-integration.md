# Клиент: запуск и передача команде

Рабочая папка: `/home/dasha/files/sem5/hahaton` (уточнение пользователя).
Исходники в Windows-папке больше не используются.

## Запуск

На ноутбуке разработчика (Node 22.12+ или установленный Node 24):

```bash
cd client
npm ci
npm run dev
```

Открыть http://localhost:5173. «Проверка 3D без сервера» запускает только
один маленький тестовый участок, три машины и геометрию знаков.
Это **не мультиплеер**, не авторизация и не серверный учебный маршрут.
WASD — управление / ходьба, пробел или S — тормоз, E — выйти после остановки,
подойти к машине / знаку и взаимодействовать. Щелчок по сцене захватывает мышь,
Esc освобождает. В preview нет учебных ответов, сохранений и проверки ПДД.

В разработке Vite проксирует `/api` и `/ws` на localhost:3000.
Браузер всегда использует свой origin. Production-сервер Ани должен раздавать
`client/dist` и API/WS с одного origin, слушать 0.0.0.0:3000.
Серверный браузер открывает http://localhost:3000, остальные — LAN-адрес сервера.
`vite preview` проверяет только статическую сборку и не заменяет сервер Ани.

```bash
npm test
npm run build
```

После установки и сборки клиент не требует CDN, внешних шрифтов или API.
На клиентских ноутбуках достаточно браузера. Сборку и зависимости сервера
нужно подготовить на серверном ноутбуке до отключения интернета.

## Ане

Реализация опирается на предложение v0.1, `docs/protocol.md` не изменён.
Нужны подтверждение контракта и серверные файлы; пока в server/ только README.
Первые необходимые события: `session.ready`, `world.interest`, `state.snapshot`.
Cookie проверяется через `/api/me` до создания WebSocket.
HTTP-ошибки `{error:{code,message}}` показываются пользователю.
Переподключение ручное кнопкой с повторной проверкой сессии.
`mode` и `vehicleId` берутся из сервера; клиент не назначает прогресс.
Состояния сервера заменяют список сущностей; удалённые машины сглаживаются.

Поддержанные примитивы: objects с kind building/tree (прочее — параллелепипед),
roads по схеме v0.1, agents с kind yield/stop/crosswalk.
Позиции абсолютные; Y вверх, yaw=0 смотрит вдоль -Z.
Пока ресурсы должны быть `[]`: неподдержанные внешние ресурсы отклоняются,
а не игнорируются в учёте. GLB/текстуры требуют отдельной согласованной схемы.

**Блокер доказательства лимита:** world.interest не сообщает размеры до загрузки.
Сейчас последовательно загружаются разрешённые участки и проверяется
accountedBytes перед удержанием/отрисовкой. Старые участки освобождаются до
загрузки новых. Рабочий предел 8%, жёсткий 10% серверного totalWorldBytes.
Это не доказывает предел для загружаемого ответа и кратковременного JSON parsing.
Нужно согласовать предварительные размеры/резервирование или ограниченный
потоковый формат. Не считать этот пункт завершённым по показателю HUD.
Также canonical bytes, доверенные серверу, нужно сверить с реальными данными.

## Даше 2

Файлы `client/src/ui/` свободны. Временная оболочка в `main.ts` + `style.css`.
Рендер и единственный Network создаются в main.ts.
Серверные события транслируются как `window` CustomEvent `game:server`,
`detail` — конверт v0.1. Команды из UI:

```ts
window.dispatchEvent(new CustomEvent('game:command', {
  detail: {type:'chat.send', payload:{text:'Привет'}, requestId:crypto.randomUUID()}
}));
```

Для auth можно переиспользовать `http` из network/api.ts. Согласовать экспорт
connect и передачу экземпляра Network при интеграции; не создавать второй WS.
Серверный текст выводить через textContent. Чат и вопросы имеют maxLength.

## Даше 3

Контент мира хранить на серверной стороне, по схеме участка v0.1.
В preview есть только маленькая фикстура, она не является полным городом.
Знания и учебные проверки в клиент не добавлять. Для завершённого маршрута
нужны серверные задания, начальная позиция и машина, реальные участки.

## Проверки перед показом

Отдельно проверить: два/три настоящих браузера с сервером, занятость машин,
серверную физику, agent.ask/reply, персональную память, прогресс, перезапуск,
смену участков, корректный знаменатель учёта, ресурсы и входящие байты,
новый вход без WAN и работу localhost после отключения Wi-Fi.
Автоматизированный браузерный preview не подтверждает эти требования.

## Автоматические проверки первой сцены

`npm test` — управление, бюджет, запрет WS до проверки сессии,
выгрузка до загрузки, отклонение тяжёлого участка, устаревший ответ.

Для повторения проверки собранной версии: сначала `npm run build`,
в отдельном терминале `npm run preview -- --port 4173`, затем
`npm run test:browser`. Нужен заранее установленный Chromium Playwright
(`npx playwright install chromium` — только до автономного показа).
Можно указать существующий браузер через CHROMIUM_PATH; адрес через CLIENT_URL.
Playwright требуется только разработчику, браузерным клиентам он не нужен.

Проверено на локальной production-сборке: разгон/торможение, выход/посадка,
401 без WebSocket, HTTP/WS-фикстуры v0.1, загрузка участка и показ доли данных,
чат с безопасным выводом текста. Внешний трафик блокировался; внешних запросов
и ошибок страницы не было. Программный рендер Chromium не является замером
FPS на целевых ноутбуках. Настоящий сервер этими фикстурами не проверен.

Дополнительная проверка кода выявила и устранила две ошибки:
отменённое подключение после незавершённого `/api/me` и смену системы отсчёта
камеры при посадке/выходе. Регрессионные тесты входят в `npm test` (12 тестов).
Браузерный сценарий также повторяет загрузку/выгрузку preview трижды:
число удерживаемых геометрий и текстур возвращается к исходному.
Это проверка жизненного цикла ресурсов, не измерение точной GPU-памяти.
