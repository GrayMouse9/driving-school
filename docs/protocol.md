Общий источник договорённостей клиента и бэкенда. Пока не является описанием готового API.
Согласовать с Аней до 12:40. Изменения фиксировать здесь сразу и уведомлять владельца другой стороны.

## Общие правила

- HTTP и WebSocket на одном origin, production-порт 3000.
- HTTP пути относительные, WebSocket /ws и host текущей страницы.
- Метры, Y вверх; автомобиль движется в XZ; yaw в радианах, yaw=0 направлен вдоль -Z.
- ID — строки: playerId, vehicleId, chunkId, agentId, lessonId.
- Право на машину, допустимая позиция, состояние задания и прогресс определяются сервером.
- Время серверное, в миллисекундах Unix; последовательности inputSeq — возрастающие целые.
- Клиент не присылает свой playerId для авторизации; сервер берёт его из сессии.
- Ошибка HTTP: { "error": { "code": "...", "message": "..." } }.
- Значения в примерах иллюстративные, не являются готовыми данными всего мира.

## Авторизация

POST /api/auth/register
Запрос: { "username": "Даша", "password": "..." }
Успех 201: { "user": { "id": "p1", "username": "Даша" } }.
Создание учётной записи не считается входом; затем вызвать login.

POST /api/auth/login
Запрос: { "username": "Даша", "password": "..." }
Успех 200: { "user": { "id": "p1", "username": "Даша" } } + HttpOnly-cookie сессии.
Ошибочный пароль — 401; занятое имя при регистрации — 409.

POST /api/auth/logout
Успех 204, сессия отозвана, связанные WebSocket закрыты.

GET /api/me
Успех 200: { "user": { "id": "p1", "username": "Даша" }, "progress": [] }.
Без сессии — 401.

## Получение мира

GET /api/world/meta
Ответ:
{ "version": "world-v1", "totalWorldBytes": 10000000, "cacheBudgetBytes": 800000, "accounting": "canonical-uncompressed-unique-world-data" }

Размеры в примере условные. Сервер рассчитывает их из фактических данных и ресурсов, клиент не назначает знаменатель.
Общий манифест всех объектов клиенту не выдаётся.

GET /api/world/chunks/:id
Требует сессию и разрешение по подтверждённой позиции игрока.
Ответ:
{
  "id": "c_2_3", "version": 1,
  "origin": { "x": 128, "z": 192 }, "size": 64,
  "objects": [
    {
      "id": "building-1", "kind": "building",
      "position": { "x": 130, "y": 0, "z": 195 },
      "yaw": 0, "size": { "x": 8, "y": 12, "z": 10 },
      "color": "#e3c4a8", "collidable": true
    }
  ],
  "roads": [
    { "id": "r1", "position": { "x": 128, "y": 0, "z": 200 }, "yaw": 0, "width": 10, "length": 64 }
  ],
  "agents": [
    { "id": "sign-1", "kind": "yield", "position": { "x": 138, "y": 0, "z": 205 }, "yaw": 0 }
  ],
  "resources": [],
  "accountedBytes": 25000
}

Все position абсолютные. origin задаёт границы участка, не смещение для objects.
Типы объектов и параметры дорог нужно согласовать с владельцем рендера до создания контента.
knowledge и полные диалоги в участок не входят; их выдаёт AgentService по запросу.
Ответы мира и ресурсов — Cache-Control: no-store.
Недоступный по позиции участок — 403 OUT_OF_RANGE.
Для лимита учитываются уникальные данные удерживаемых участков, разделяемые ресурсы и загружаемые данные.

## WebSocket

Сессия проверяется ДО upgrade; без неё HTTP 401.
Входящие сообщения проверяются по типу и структуре, неизвестные поля не исполняются.

Конверт запроса:
{ "v": 1, "type": "agent.ask", "requestId": "req-12", "payload": {} }

requestId нужен операциям с ответом. Поток управления использует seq.
Идемпотентность важных операций и привязка ответа к запросу не должны зависеть от порядка UI-окон.

Клиент → сервер:
- player.input: { seq, throttle, brake, steer, moveX, moveZ, lookYaw }.
  throttle/brake: 0..1; steer/moveX/moveZ: -1..1; lookYaw: радианы.
  Движение автомобиля — серверная упрощённая модель; если выбирается другая схема, изменить контракт до реализации.
- vehicle.enter: { vehicleId }.
- vehicle.exit: {}. Сервер проверяет остановку и точку выхода.
- chat.send: { text }. Максимум 500 символов.
- agent.ask: { agentId, text }. Максимум 1000 символов; сервер проверяет дистанцию.
- lesson.start: { lessonId }.
- lesson.answer: { taskId, answer }. Формат answer задаёт конкретное задание.

Сервер → клиент:

session.ready:
{
  "selfId": "p1", "tickRate": 20,
  "player": {
    "id": "p1", "username": "Даша",
    "position": { "x": 0, "y": 0, "z": 0 },
    "yaw": 0, "mode": "onFoot", "vehicleId": null
  },
  "vehicles": [], "progress": []
}
vehicles содержит доступные в текущем окружении машины, не весь город.

world.interest:
{
  "allowedChunkIds": ["c_0_0", "c_0_1"],
  "removeChunkIds": [], "cacheBudgetBytes": 800000
}
Это заменяет текущий список разрешённых участков. Клиент выгружает remove, резервирует бюджет и получает недостающие.
Сервер не должен разрешать минимальный набор данных, который невозможно вместить.

state.snapshot:
{
  "tick": 12, "serverTime": 1793440000000, "ackInputSeq": 10,
  "players": [],
  "vehicles": [
    {
      "id": "v1", "driverId": "p1", "variant": "blue",
      "position": { "x": 1, "y": 0, "z": 2 }, "yaw": 0, "speed": 0
    }
  ]
}
players использует ту же структуру, что session.ready.player.
speed — м/с; UI переводит в км/ч. Набор сущностей в каждом snapshot заменяет известный набор в области интереса, что позволяет убирать исчезнувших игроков.
Для собственного игрока требуется регулярное подтверждённое состояние.

chat.message:
{ "senderId": "p1", "username": "Даша", "text": "Привет", "serverTime": 1793440000000 }

agent.reply:
{
  "agentId": "sign-1", "name": "Уступите дорогу",
  "text": "Посмотрим на траектории участников.",
  "topic": "priority", "exampleId": "priority-example-2",
  "suggestedQuestions": ["Покажи другой пример"]
}
Ответ содержит исходный requestId. Имя знака не используется как авторизационный идентификатор.

lesson.feedback:
{ "taskId": "task-1", "correct": false, "explanation": "...", "nextTaskId": null }

progress.updated:
{ "lessons": [], "learnedTopics": ["priority"], "mistakes": [] }

error:
{ "code": "OUT_OF_RANGE", "message": "Подойдите ближе к знаку" }
При ответе на операцию приложить исходный requestId.

Коды: UNAUTHENTICATED, INVALID_MESSAGE, OUT_OF_RANGE, VEHICLE_BUSY, WORLD_BUDGET_EXCEEDED.

## Переподключение и сохранение

При потере соединения UI показывает статус и перестаёт принимать новые игровые команды.
После переподключения session.ready и первый snapshot восстанавливают актуальное состояние.
Сервер освобождает машину отключённого игрока по согласованному тайм-ауту и не допускает двух водителей.
Критический прогресс и память сохраняются после события; координаты периодически.
Никакой зависимости от IP домашнего ноутбука Ани.
