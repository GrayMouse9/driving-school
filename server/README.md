# Сервер

Контракт: `../docs/архитектура.md`. Go-сервер обслуживает HTTP и WebSocket,
сохраняет данные в PostgreSQL и раздаёт собранный клиент с того же origin.

## Запуск в Ubuntu

Нужны Go 1.22 или новее, доступная база PostgreSQL и её адрес в переменной
`DATABASE_URL`. База и пользователь должны быть созданы заранее, пользователь
должен иметь право создавать таблицы. Не сохраняйте пароль в репозитории.

Из каталога `server/` задайте `DATABASE_URL` в окружении и запустите:

```sh
WORLD_FILE=testdata/development-world.json go run ./cmd/server
```

По умолчанию сервер слушает `:8080` и раздаёт `../client/dist`. Переменные
`LISTEN_ADDR` и `CLIENT_DIR` позволяют изменить адрес и каталог сборки клиента.
Схема таблиц создаётся при запуске, если их ещё нет. Проверка доступности:
`GET /api/v1/health`.

`testdata/development-world.json` — карта для разработки, не учебный сценарий.
Её можно восстановить командой `node testdata/generate-world.mjs`. Формат:
`version`, `spawnPoints` (`x`, `y`, `z`, `yaw`) и `chunks`; участки используют
структуру `Chunk` из архитектуры. В MVP `resources` должен быть пустым массивом.
Для рабочего мира укажите `WORLD_FILE` на подготовленный файл того же формата.

## Проверки

```sh
go test ./...
go build ./...
```

Тесты с реальным PostgreSQL пропускаются без `DRIVING_SCHOOL_TEST_DATABASE_URL`.
Указывайте для них только отдельную тестовую базу: тест создаёт таблицы и
временных пользователей. Клиент пока использует старый протокол и не проверен
с этим сервером. Учебные эпизоды, автобус и интеграция с ИИ ещё не реализованы.
